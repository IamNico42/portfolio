# Verkehrslenkung

## Was ist Verkehrslenkung?
**Verkehrslenkung** beschreibt, wie Daten innerhalb eines lokalen Netzes und über mehrere Netze hinweg zum richtigen Ziel gelangen.

Ein Endgerät kennt normalerweise nicht den vollständigen Weg zum Ziel. Stattdessen entscheidet jeder beteiligte Switch oder Router nur, an welchen nächsten Netzknoten die Daten weitergegeben werden.

Dabei werden zwei Arten von Datenübertragung unterschieden:

| Bereich | Verwendete Adresse | Zuständiges Gerät |
|---|---|---|
| Innerhalb eines lokalen Netzes | MAC-Adresse | Switch beziehungsweise Bridge |
| Zwischen verschiedenen IP-Netzen | IP-Adresse | Router |

Das Internet besteht zusätzlich aus vielen großen, voneinander verwalteten Netzen. Diese werden **Autonome Systeme** genannt.

---

## Grundaufbau des Internets

### Lokales Netz
Ein **Local Area Network (LAN)** verbindet Geräte in einem räumlich begrenzten Bereich. Das kann beispielsweise ein Heimnetz, ein Hochschulnetz oder ein Firmennetz sein.

Innerhalb des LANs erfolgt die Weiterleitung anhand von MAC-Adressen. Switches verbinden die einzelnen Geräte und LAN-Segmente.

### Autonomes System
Ein **Autonomes System (AS)** ist ein IP-Netz, das von einer gemeinsamen Organisation verwaltet wird.

Beispiele dafür sind:

- das Netz eines Internetproviders
- das Netz einer großen Universität
- das Netz eines internationalen Unternehmens

Die Router innerhalb eines Autonomen Systems verwenden gemeinsame Routingverfahren und Routingregeln.

### Verbindung mehrerer Autonomer Systeme
Das Internet entsteht durch die Verbindung vieler Autonomer Systeme.

Spezielle **Border-Router** verbinden ein Autonomes System mit anderen Autonomen Systemen. Sie müssen nicht nur technische Pfadkosten berücksichtigen, sondern auch wirtschaftliche Vereinbarungen zwischen den Netzbetreibern.

---

## Switches und Router

### Switch
Ein Switch verbindet Geräte innerhalb eines LANs.
Seine wichtigsten Eigenschaften sind:

- Weiterleitung anhand der Ziel-MAC-Adresse
- selbständiges Lernen der erreichbaren MAC-Adressen
- Trennung von Kollisionsdomänen
- Weiterleitung von Broadcasts innerhalb des LANs

Ein Switch betrachtet normalerweise keine IP-Routingtabelle. Für seine Entscheidung ist entscheidend, an welchem Port eine MAC-Adresse erreichbar ist.

### Router
Ein Router verbindet unterschiedliche IP-Netze beziehungsweise Subnetze.
Seine wichtigsten Eigenschaften sind:

- Weiterleitung anhand der Ziel-IP-Adresse
- Verwendung einer Routingtabelle
- Verbindung verschiedener Netzwerksegmente
- Begrenzung von Broadcast-Domänen

Jedes Router-Interface gehört normalerweise zu einem eigenen Netzwerksegment und besitzt eine passende IP-Adresse.

### Border-Router
Ein Border-Router befindet sich am Rand eines Autonomen Systems.
Er erfüllt zwei Aufgaben:

1. Er verwendet ein internes Routingverfahren, um Ziele im eigenen Autonomen System zu erreichen.
2. Er tauscht mit anderen Autonomen Systemen Informationen über externe Ziele aus.

---

## Verkehrslenkung im LAN

### Warum werden MAC-Adressen benötigt?
Ethernet und WLAN übertragen Daten innerhalb eines lokalen Netzwerksegments. Dafür verwenden sie MAC-Adressen.

Eine MAC-Adresse identifiziert eine Netzwerkschnittstelle innerhalb des LANs. Im Gegensatz zu einer IP-Adresse enthält sie normalerweise keine hierarchische Information über den Standort des Geräts.

Ein Switch kann deshalb nicht allein aus einer MAC-Adresse erkennen, an welchem Port sich das Gerät befindet. Er muss diese Zuordnung erst lernen.

---

## Frame Forwarding Table
Jeder Switch besitzt eine **Frame Forwarding Table**. Sie speichert, über welchen Port eine bekannte MAC-Adresse erreichbar ist.

| MAC-Adresse | Port | Alter des Eintrags |
|---|---:|---:|
| `00:00:00:00:00:AA` | 1 | 10 Sekunden |
| `00:00:00:00:00:BB` | 2 | 2 Minuten |
| `00:00:00:00:00:CC` | 3 | 30 Sekunden |

Die Einträge besitzen eine begrenzte Gültigkeitsdauer. Dadurch kann sich die Tabelle anpassen, wenn ein Gerät das LAN verlässt oder an einen anderen Port angeschlossen wird.

---

## Wie lernt ein Switch MAC-Adressen?
Der Switch lernt anhand der **Quell-MAC-Adresse** eines ankommenden Frames.

### Beispiel
Ein Frame mit der Quelladresse `AA` kommt an Port 2 an.
Der Switch speichert anschließend:

```text
MAC-Adresse AA befindet sich an Port 2.
```

Kommt später erneut ein Frame von `AA` an Port 2 an, wird die Gültigkeitsdauer des Eintrags erneuert.

Kommt ein Frame von `AA` plötzlich an Port 4 an, wird der Eintrag auf Port 4 aktualisiert.

> Ein Switch lernt anhand der Quelladresse, entscheidet aber anhand der Zieladresse.

---

## Wie leitet ein Switch Frames weiter?

### Zieladresse ist bekannt
Ist die Ziel-MAC-Adresse in der Forwarding Table vorhanden, sendet der Switch den Frame nur über den gespeicherten Port.
Dadurch müssen andere Geräte im LAN den Frame nicht verarbeiten.

### Zieladresse ist unbekannt
Ist die Ziel-MAC-Adresse noch nicht bekannt, verteilt der Switch den Frame auf alle geeigneten Ports außer dem Eingangsport.
Dieses Verhalten heißt **Flooding**.
Der Zielhost antwortet normalerweise auf den Frame. Anhand dieser Antwort kann der Switch anschließend auch dessen MAC-Adresse lernen.

### Ziel befindet sich am Eingangsport
Hat der Switch gelernt, dass sich das Ziel am gleichen Port wie der Sender befindet, muss der Frame nicht über einen anderen Port weitergeleitet werden.

### Broadcast
Ein Broadcast ist für alle Geräte innerhalb des LANs bestimmt. Der Switch verteilt ihn deshalb auf alle geeigneten Ports außer dem Eingangsport.

---

## Beispiel zum MAC-Learning
Die Forwarding Table eines Switches ist zunächst leer.

### Erster Frame
Host `AA` sendet einen Frame an Host `CC`.

- Der Switch lernt die Quelladresse `AA`.
- Die Zieladresse `CC` ist unbekannt.
- Der Frame wird im LAN verteilt.

### Antwort
Host `CC` antwortet an Host `AA`.

- Der Switch lernt die Quelladresse `CC`.
- Die Zieladresse `AA` ist bereits bekannt.
- Die Antwort wird nur über den Port von `AA` weitergeleitet.

Danach kennt der Switch beide Zuordnungen:

| MAC-Adresse | Port |
|---|---:|
| `AA` | 1 |
| `CC` | 3 |

---

## Schleifen in einem Switch-Netz
Redundante Verbindungen erhöhen die Ausfallsicherheit. Sie können aber dazu führen, dass zwischen Switches eine Schleife entsteht.

Das ist besonders bei Broadcasts problematisch:

- Ein Switch verteilt den Broadcast.
- Ein anderer Switch empfängt und verteilt ihn ebenfalls.
- Durch die Schleife gelangt derselbe Broadcast wieder zum ersten Switch.
- Ethernet besitzt für Frames keine mit der IP-TTL vergleichbare Begrenzung.

Mögliche Folgen sind:

- Broadcast Storm
- mehrfach empfangene Frames
- ständig wechselnde Einträge in den Forwarding Tables
- Ãœberlastung des gesamten LANs

---

## Spanning Tree Protocol
Das **Spanning Tree Protocol (STP)** verhindert Schleifen in einem Netz mit redundanten Switch-Verbindungen.

STP bestimmt aus der vorhandenen Topologie einen schleifenfreien Spannbaum. Alle Switches bleiben erreichbar, aber einige redundante Ports werden logisch blockiert.

### Grundprinzip
1. Die Switches bestimmen eine Root Bridge.
2. Jeder Switch bestimmt seinen günstigsten Weg zur Root Bridge.
3. Die benötigten Verbindungen bleiben aktiv.
4. Redundante Verbindungen werden blockiert.

Die Kabel bleiben physisch angeschlossen. Fällt eine aktive Verbindung aus, kann STP einen zuvor blockierten Weg aktivieren.

### Warum wird kein minimaler Spannbaum nach Kruskal verwendet?
Das Ziel von STP ist in erster Linie ein **schleifenfreies Ethernet-Netz**. Der berechnete Baum wird anhand der Root Bridge und der Pfadkosten zu dieser Root Bridge aufgebaut.

Das ist nicht dasselbe wie Kruskals Aufgabe, die Summe aller Kantengewichte eines Graphen global zu minimieren.

---

## VLAN
Ein **Virtual Local Area Network (VLAN)** teilt ein physisches Switch-Netz in mehrere logische LANs.

Geräte können am gleichen Switch angeschlossen sein und trotzdem unterschiedlichen VLANs angehören.

### Eigenschaften
- Jedes VLAN bildet eine eigene Broadcast-Domäne.
- Broadcasts werden nur innerhalb des jeweiligen VLANs verteilt.
- Geräte verschiedener VLANs können nicht direkt auf Layer 2 miteinander kommunizieren.
- Für die Kommunikation zwischen VLANs wird ein Router oder Layer-3-Switch benötigt.

### Port-basiertes VLAN
Ein Port wird fest einem VLAN zugeordnet.

| Switch-Ports | VLAN |
|---|---:|
| Port 1 bis 4 | VLAN 10 |
| Port 5 bis 8 | VLAN 20 |

Ein unmarkierter Frame, der an Port 2 ankommt, wird dadurch VLAN 10 zugeordnet.

### VLAN-Tagging
Zwischen Switches müssen häufig Frames mehrerer VLANs über eine gemeinsame Leitung übertragen werden.

Dafür enthält der Ethernet-Frame ein VLAN-Tag. Dieses Tag gibt an, zu welchem VLAN der Frame gehört.

Ein Port, über den mehrere markierte VLANs übertragen werden, heißt **Trunk-Port**.

## IP-Adressen und Subnetze

### Warum sind IP-Adressen hierarchisch?
Eine einzelne Routingtabelle kann nicht für jede mögliche IP-Adresse einen eigenen Eintrag enthalten.

IP-Adressen werden deshalb in zusammenhängende Adressbereiche gegliedert. Router speichern Routen zu diesen Bereichen und nicht zu jedem einzelnen Endgerät.

Eine IPv4-Adresse besteht logisch aus:

- einem Netzpräfix
- einem Hostanteil

Die Netzmaske bestimmt, wie viele Bits zum Präfix gehören.

---

## Adressbereich und Präfixlänge
Beispiel:

```text
141.37.168.32/27
```

Die Präfixlänge `/27` bedeutet:

- 27 Bit gehören zum Netzpräfix.
- 5 Bit bleiben für Adressen innerhalb des Bereichs.
- Der Bereich enthält insgesamt 32 Adressen.

Die Anzahl der Adressen wird berechnet mit:

$$
\text{Anzahl der Adressen}=2^{32-\text{Präfixlänge}}
$$

Für `/27` gilt:

$$
2^{32-27}=2^5=32
$$

Der Adressbereich lautet:

```text
141.37.168.32 bis 141.37.168.63
```

---

## Netzwerksegmente
Ein Router verbindet mehrere Netzwerksegmente.

Jedes Segment benötigt einen eigenen Adressbereich. Die Geräte eines Segments besitzen Adressen aus diesem gemeinsamen Bereich.

### Beispiel

| Netzwerksegment | Adressbereich | Router-Adresse |
|---|---|---|
| LAN 1 | `192.168.10.0/24` | `192.168.10.1` |
| LAN 2 | `192.168.20.0/24` | `192.168.20.1` |

Der Router besitzt in diesem Beispiel zwei Interfaces. Jedes Interface gehört zu einem anderen Subnetz.

---

## Routing und Forwarding
Die Begriffe **Routing** und **Forwarding** beschreiben unterschiedliche Aufgaben.

### Routing

Routing bestimmt, welche Wege durch das Netz verwendet werden sollen.

Routingprotokolle tauschen Informationen über Netze, Router und Pfadkosten aus. Aus diesen Informationen entstehen Routingtabellen.

### Forwarding

Forwarding ist die konkrete Entscheidung für ein einzelnes Paket.

Der Router betrachtet die Ziel-IP-Adresse, sucht den passenden Eintrag in seiner Routingtabelle und gibt das Paket über das bestimmte Interface weiter.

| Begriff | Bedeutung |
|---|---|
| Routing | Routen berechnen und Routinginformationen austauschen |
| Forwarding | Ein konkretes Paket anhand der Routingtabelle weiterleiten |

---

## Aufbau einer Routingtabelle
Eine Route enthält normalerweise folgende Angaben:

| Bestandteil | Bedeutung |
|---|---|
| Zielnetz | Adressbereich, für den die Route gilt |
| Netzmaske oder Präfixlänge | Größe des Adressbereichs |
| Next Hop | IP-Adresse des nächsten Routers |
| Interface | Lokale Netzwerkschnittstelle |
| Metrik | Kosten der Route |

Eine besondere Route ist die **Default-Route**:

```text
0.0.0.0/0
```

Sie passt auf jede IPv4-Adresse. Sie wird verwendet, wenn keine spezifischere Route vorhanden ist.

---

## Longest Prefix Match
Eine Zieladresse kann zu mehreren Einträgen der Routingtabelle passen.

In diesem Fall wird die Route mit dem längsten passenden Präfix gewählt. Sie beschreibt den kleinsten und damit genauesten passenden Adressbereich.

### Beispiel

| Zielnetz | Präfixlänge | Router |
|---|---:|---|
| `0.0.0.0` | `/0` | Router 4 |
| `128.0.0.0` | `/8` | Router 2 |
| `128.42.0.0` | `/16` | Router 3 |
| `128.42.222.0` | `/24` | Router 1 |

Gesucht ist die Route für:

```text
128.42.222.198
```

Die Adresse passt zu allen vier Einträgen. Der Eintrag `128.42.222.0/24` besitzt aber das längste Präfix und wird deshalb gewählt.

### Vorgehensweise in einer Aufgabe
1. Prüfe, welche Routen zur Zieladresse passen.
2. Vergleiche die Präfixlängen der passenden Routen.
3. Wähle die Route mit der größten Präfixlänge.
4. Gibt es mehrere gleich spezifische Routen, kann die Metrik entscheiden.
5. Passt keine spezifische Route, wird die Default-Route verwendet.

> Die Präfixlänge wird vor der Metrik betrachtet.

---

## Direkte und indirekte Route

### Direkt angeschlossenes Netz
Liegt das Ziel im gleichen Netzwerksegment wie das Router-Interface, ist kein weiterer Router notwendig.

Die Route wird häufig als **on route** oder **directly connected** bezeichnet.

### Ziel in einem entfernten Netz
Liegt das Ziel in einem anderen Netz, enthält der Routingtabelleneintrag einen Next Hop.

Dieser Next Hop muss über das angegebene lokale Interface erreichbar sein.

---

## ARP im Zusammenhang mit Routing
ARP ermittelt innerhalb eines lokalen IPv4-Netzes die MAC-Adresse zu einer IP-Adresse.

### Ziel liegt im eigenen Subnetz
Der Sender benötigt die MAC-Adresse des Zielhosts.

Er sendet eine ARP-Anfrage und verwendet die erhaltene MAC-Adresse für den Ethernet-Frame.

### Ziel liegt in einem fremden Subnetz
Der Sender kann den entfernten Zielhost nicht direkt über Ethernet erreichen.

Er benötigt deshalb die MAC-Adresse seines Default-Gateways.

Der Ethernet-Frame ist an den Router adressiert. Die Ziel-IP-Adresse im enthaltenen IP-Paket bleibt trotzdem die Adresse des endgültigen Zielhosts.

### Änderung der Adressen unterwegs

| Adresse | Verhalten über mehrere Router |
|---|---|
| Ziel-IP-Adresse | bleibt normalerweise die Adresse des endgültigen Ziels |
| Quell-IP-Adresse | bleibt ohne NAT normalerweise unverändert |
| Ziel-MAC-Adresse | wird für jedes Netzwerksegment neu gesetzt |
| Quell-MAC-Adresse | wird für jedes Netzwerksegment neu gesetzt |

---

## Intra-Domain-Routing
Intra-Domain-Routing bezeichnet das Routing innerhalb eines Autonomen Systems.

Die Netzstruktur wird als gewichteter Graph betrachtet:

- Router bilden die Knoten.
- Verbindungen bilden die Kanten.
- Jede Verbindung besitzt Kosten.

Die Kosten können beispielsweise von der Bandbreite, Verzögerung oder administrativen Konfiguration abhängen.

Gesucht wird ein geeigneter Pfad mit möglichst geringen Gesamtkosten.

---

## Link-State-Routing
Beim Link-State-Routing kennt jeder Router die vollständige Topologie des betrachteten Netzes.

### Ablauf
1. Jeder Router erkennt seine direkten Nachbarn.
2. Der Router bestimmt die Kosten seiner direkten Verbindungen.
3. Diese Informationen werden im Netz verteilt.
4. Jeder Router baut daraus eine vollständige Sicht auf die Topologie auf.
5. Jeder Router berechnet die kürzesten Pfade lokal mit dem Dijkstra-Algorithmus.

Das Verteilen der Linkinformationen an alle Router heißt **Flooding**.

### Eigenschaften
- Jeder Router besitzt eine vollständige Topologiesicht.
- Die Routen werden lokal berechnet.
- Änderungen einer Verbindung müssen im gesamten Routingbereich verteilt werden.
- Alle Router verwenden grundsätzlich dieselben Topologieinformationen.

### Wichtige Protokolle
- OSPF
- IS-IS

---

## Distance-Vector-Routing
Beim Distance-Vector-Routing kennt ein Router nicht die vollständige Topologie.
Er kennt:

- seine direkten Nachbarn
- die Kosten zu diesen Nachbarn
- die von den Nachbarn gemeldeten Kosten zu weiteren Zielen

Der Router berechnet für jedes Ziel, über welchen Nachbarn die geringsten Gesamtkosten entstehen.

Die grundlegende Berechnung lautet:

$$
D_x(y)=\min_v\left(c(x,v)+D_v(y)\right)
$$

- $D_x(y)$ ist die aktuelle Distanz von Router $x$ zum Ziel $y$.
- $c(x,v)$ sind die direkten Kosten von Router $x$ zum Nachbarn $v$.
- $D_v(y)$ ist die von Nachbar $v$ gemeldete Distanz zum Ziel $y$.

### Beispiel
Router A erreicht Router B mit Kosten 2. Router B meldet Kosten 3 zum Ziel D.
Die Kosten von A über B nach D betragen:

$$
2+3=5
$$

Meldet ein anderer Nachbar Gesamtkosten von 7, wird die Route über B gewählt.

### Wichtige Protokolle

- RIP
- EIGRP

---

## Vergleich von Link State und Distance Vector

| Eigenschaft | Link State | Distance Vector |
|---|---|---|
| Wissen des Routers | vollständige Topologie | Informationen der direkten Nachbarn |
| Berechnung | lokal auf jedem Router | verteilt und schrittweise |
| Grundalgorithmus | Dijkstra | Bellman-Ford |
| Informationsaustausch | Zustand der eigenen Verbindungen | bekannte Distanzen zu Zielen |
| Beispiele | OSPF, IS-IS | RIP, EIGRP |

Keines der beiden Verfahren ist in jeder Situation grundsätzlich besser. Die konkrete Eignung hängt von Netzgröße, Konvergenz, Geräteunterstützung und Konfiguration ab.

---

## Routingmetriken
Eine Routingmetrik beschreibt die Kosten eines Links oder eines gesamten Pfads.
Mögliche Werte sind:

- Anzahl der Router beziehungsweise Hops
- verfügbare Bandbreite
- Verzögerung
- Auslastung
- Zuverlässigkeit
- administrativ festgelegte Kosten

### RIP
RIP verwendet den Hop Count.

- Jeder durchlaufene Router erhöht die Metrik um 1.
- Der Wert 16 gilt als unerreichbar.
- Dadurch eignet sich RIP nur für relativ kleine Netze.

### OSPF
OSPF verwendet konfigurierbare Linkkosten. Standardmäßig werden diese häufig aus der Bandbreite abgeleitet.

Ein Pfad mit wenigen Hops muss deshalb nicht zwingend der günstigste OSPF-Pfad sein.

---

## Inter-Domain-Routing
Inter-Domain-Routing bezeichnet das Routing zwischen verschiedenen Autonomen Systemen.

Das zentrale Protokoll dafür ist **BGP**, das Border Gateway Protocol.

Bei BGP ist nicht nur die technische Qualität eines Pfads wichtig. Netzbetreiber berücksichtigen auch:

- Kundenbeziehungen
- Providerverträge
- Peering-Abkommen
- Kosten
- Sicherheits- und Unternehmensrichtlinien

Der technisch kürzeste Pfad wird deshalb nicht automatisch ausgewählt.

---

## eBGP und iBGP

### eBGP
External BGP wird zwischen Border-Routern verschiedener Autonomer Systeme verwendet.

Die Router informieren sich gegenseitig darüber, welche IP-Präfixe über das jeweilige Autonome System erreichbar sind.

### iBGP
Internal BGP verteilt extern gelernte BGP-Routen innerhalb des eigenen Autonomen Systems.

Dadurch erfahren interne BGP-Router:

- welche externen Präfixe erreichbar sind
- welcher Border-Router verwendet werden kann
- welche BGP-Attribute und Policies für die Route gelten

Ein normales internes Routingprotokoll wie OSPF kann zwar den Weg zu einem Border-Router berechnen, überträgt aber nicht alle BGP-Policies.

---

## BGP als Path-Vector-Protokoll
Eine BGP-Route enthält nicht nur eine Distanz, sondern unter anderem den durchlaufenen AS-Pfad.

Beispiel:

```text
Zielpräfix: 120.10.0.0/16
AS-Pfad: AS 2, AS 3, AS 4
```

Der AS-Pfad erfüllt zwei wichtige Aufgaben:

1. Er zeigt, durch welche Autonomen Systeme die Route verläuft.
2. Er hilft bei der Erkennung von Routing-Schleifen.

Enthält eine empfangene Route bereits die eigene AS-Nummer, wird sie normalerweise verworfen.

---

## Beziehungen zwischen Autonomen Systemen

### Customer und Provider
Ein Customer bezahlt einen Provider für die Verbindung zum restlichen Internet.

Der Provider transportiert Verkehr des Customers zu externen Netzen und Verkehr aus dem Internet zum Customer.

### Peering
Beim Peering tauschen zwei Autonome Systeme Verkehr zu ihren eigenen Netzen und ihren Kundennetzen aus.

Ein Peer hat normalerweise keinen wirtschaftlichen Grund, kostenlos Verkehr zwischen zwei anderen Providern oder Peers zu transportieren.

### Typische Exportregeln

| Empfänger einer Route | Typischerweise angebotene Routen |
|---|---|
| Customer | alle benötigten erreichbaren Routen |
| Peer | eigene Routen und Routen der eigenen Customers |
| Provider | eigene Routen und Routen der eigenen Customers |

Diese Regeln verhindern, dass ein Netz unbeabsichtigt kostenlosen Transitverkehr für andere Provider übernimmt.

---

## BGP-Routenauswahl
Die genaue Routenauswahl ist nicht weltweit einheitlich. Sie wird vom jeweiligen Netzbetreiber konfiguriert.

Eine typische Reihenfolge aus der Vorlesung ist:

1. höchste Local Preference
2. kürzester AS-Pfad
3. niedrigster MED
4. niedrigste interne Kosten zum Border-Router
5. Router-ID als letzte Entscheidung

### Local Preference
Die Local Preference wird innerhalb des eigenen Autonomen Systems verwendet.

Eine Route mit höherer Local Preference wird bevorzugt. Damit kann ein Betreiber festlegen, über welchen Nachbarn ausgehender Verkehr das eigene Netz verlassen soll.

### MED
Der Multi-Exit Discriminator wird einem benachbarten Autonomen System mitgeteilt.

Ein niedrigerer MED wird normalerweise bevorzugt. Damit kann ein Netz angeben, über welchen von mehreren Ãœbergängen eingehender Verkehr bevorzugt werden soll.

### Hot-Potato-Routing

Beim Hot-Potato-Routing wird Verkehr möglichst früh an das nächste Autonome System übergeben.

Das eigene Netz wählt dafür den intern günstigsten Border-Router. Der gesamte Weg bis zum endgültigen Ziel kann dadurch trotzdem länger sein.

---

## IPv4 im Zusammenhang mit Verkehrslenkung
Das IP-Protokoll selbst berechnet keine Routen. Routingprotokolle erzeugen die Routinginformationen, während IPv4 das Format der weiterzuleitenden Pakete festlegt.

Wichtige IPv4-Headerfelder sind:

| Feld | Bedeutung |
|---|---|
| Source Address | IP-Adresse des Senders |
| Destination Address | IP-Adresse des Empfängers |
| TTL | begrenzt die Anzahl möglicher Router-Hops |
| Protocol ID | kennzeichnet beispielsweise TCP, UDP oder ICMP |
| Total Length | Gesamtlänge des IP-Pakets |
| Identifier, Flags und Fragment Offset | Steuerung der Fragmentierung |
| DSCP | differenzierte Behandlung von Paketen |
| ECN | Signalisierung bevorstehender Ãœberlast |

Jeder Router reduziert die TTL. Erreicht sie den Wert 0, wird das Paket verworfen. Dadurch können IP-Pakete nicht unbegrenzt in einer Routing-Schleife zirkulieren.

---

## IPv4-Fragmentierung
Unterschiedliche Layer-2-Netze können unterschiedliche MTUs besitzen.

Ist ein IPv4-Paket größer als die MTU des nächsten Links, kann es fragmentiert werden, sofern das Fragment-Bit nicht gesetzt ist.

### Benötigte Felder

- **Identifier:** ordnet alle Fragmente dem ursprünglichen Paket zu.
- **More Fragments:** zeigt an, ob weitere Fragmente folgen.
- **Fragment Offset:** beschreibt die Position der Fragmentdaten im ursprünglichen Paket.

Die Wiederzusammensetzung erfolgt erst am Zielhost.

> Im echten IPv4-Header wird der Fragment Offset in Einheiten von 8 Byte gespeichert. Aufgaben oder vereinfachte Abbildungen können stattdessen direkt die Byteposition angeben.

Fragmentierung verursacht zusätzlichen Aufwand und wird deshalb möglichst durch Path MTU Discovery vermieden.

## DHCP
Ein Endgerät benötigt für die Kommunikation mindestens:

- eine eigene IP-Adresse
- eine Subnetzmaske
- ein Default-Gateway
- die Adresse eines DNS-Servers

DHCP kann diese Werte automatisch zuweisen.

### Grundlegender Ablauf

1. Der Client sucht nach verfügbaren DHCP-Servern.
2. Ein Server bietet eine Konfiguration an.
3. Der Client fordert das gewählte Angebot an.
4. Der Server bestätigt die Zuweisung.

Da der Client anfangs noch keine eigene IP-Adresse kennt, werden die ersten Nachrichten als Broadcast übertragen.

DHCP verwendet:

| Teilnehmer | UDP-Port |
|---|---:|
| Server | 67 |
| Client | 68 |

## NAT
Private IPv4-Adressen sind im öffentlichen Internet nicht eindeutig und werden dort normalerweise nicht geroutet.

Wichtige private Bereiche sind:

| Privater Adressbereich | Präfix |
|---|---|
| `10.0.0.0` bis `10.255.255.255` | `/8` |
| `172.16.0.0` bis `172.31.255.255` | `/12` |
| `192.168.0.0` bis `192.168.255.255` | `/16` |

Ein NAT-Router übersetzt private Adressen in eine öffentliche Adresse.

### NAPT
In der Praxis wird meist nicht nur die IP-Adresse, sondern auch der Transportport übersetzt.

Beispiel:

| Interne Verbindung | Ã–ffentliche Zuordnung |
|---|---|
| `192.168.0.2:2345` | `66.31.210.69:50001` |
| `192.168.0.3:2345` | `66.31.210.69:50002` |

Die unterschiedlichen öffentlichen Ports ermöglichen es, Antwortpakete dem richtigen internen Socket zuzuordnen.

### Eingehende Verbindungen
Eine neue Verbindung aus dem Internet besitzt zunächst keinen passenden NAT-Eintrag.

Mögliche Lösungen sind:

- Port Forwarding
- NAT Hole Punching
- STUN
- TURN

STUN hilft einem Client dabei, seine öffentliche NAT-Zuordnung festzustellen. TURN leitet den Verkehr über einen öffentlich erreichbaren Server und funktioniert deshalb auch in Situationen, in denen keine direkte Verbindung hergestellt werden kann.

## IPv6
IPv6 verwendet 128-Bit-Adressen und stellt dadurch einen wesentlich größeren Adressraum bereit.
Beispiel:

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7344
```

Verkürzte Schreibweise:

```text
2001:db8:85a3::8a2e:370:7344
```

### Unterschiede zu IPv4

| IPv4 | IPv6 |
|---|---|
| 32-Bit-Adressen | 128-Bit-Adressen |
| variabler Basisheader | Basisheader mit 40 Byte |
| Header-Checksum vorhanden | keine Header-Checksum |
| Router können fragmentieren | Router fragmentieren nicht |
| Optionen im normalen Header | zusätzliche Extension Header |

### Koexistenz von IPv4 und IPv6
Der Wechsel zu IPv6 erfolgt schrittweise. Deshalb existieren verschiedene Ãœbergangstechniken:

- Dual Stack mit IPv4 und IPv6
- Tunneling eines Protokolls durch das andere
- Ãœbersetzung zwischen IPv4 und IPv6
- DS-Lite mit einem IPv6-Zugangsnetz und zentraler IPv4-NAT-Funktion

## Mobilitätsunterstützung
Eine IP-Adresse beschreibt nicht nur einen Kommunikationsendpunkt, sondern auch dessen Position im Netz.

Wechselt ein mobiles Gerät in ein anderes Subnetz, benötigt es normalerweise eine neue lokale IP-Adresse. Bestehende TCP-Verbindungen verwenden jedoch weiterhin die bisherige Adresse.

### Mobilitätsanker
Ein Mobilitätsanker ermöglicht die Verwendung einer dauerhaft bekannten Adresse.

Das mobile Gerät besitzt:

- eine statische Home-IP-Adresse
- eine aktuelle lokale IP-Adresse

Der Mobilitätsanker speichert die Zuordnung zwischen beiden Adressen.

Pakete an die Home-IP-Adresse gelangen zunächst zum Mobilitätsanker. Dieser kapselt sie in ein weiteres IP-Paket und sendet sie zur aktuellen lokalen Adresse des Geräts.

### Subnetzwechsel
1. Das Gerät wechselt in ein neues Subnetz.
2. Es erhält eine neue lokale IP-Adresse.
3. Es teilt dem Mobilitätsanker die neue Adresse mit.
4. Der Mobilitätsanker aktualisiert die Zuordnung.
5. Weitere Pakete werden zum neuen Standort getunnelt.

Die statische Adresse bleibt für Anwendungen und bestehende Verbindungen unverändert.

## Tunneling
Beim Tunneling wird ein vollständiges Paket in ein weiteres Paket eingebettet.

Der äußere Header dient der Ãœbertragung zwischen den Tunnelendpunkten. Das ursprüngliche Paket bleibt im Inneren erhalten.

Zwischenliegende Router betrachten nur den äußeren Header. Am Tunnelausgang wird dieser entfernt und das ursprüngliche Paket weiterverarbeitet.

Beispiele sind:

- VPN-Tunnel
- GRE
- IP-in-IP
- GTP in Mobilfunknetzen

## Zusammenhang der wichtigsten Verfahren

| Situation | Benötigtes Verfahren |
|---|---|
| Frame innerhalb eines LANs weiterleiten | MAC-Learning und Switching |
| Schleifen zwischen Switches verhindern | Spanning Tree |
| Ein physisches LAN logisch aufteilen | VLAN |
| Zielnetz anhand einer IP-Adresse bestimmen | Routingtabelle und Longest Prefix Match |
| MAC-Adresse im lokalen IPv4-Segment bestimmen | ARP |
| Routen innerhalb eines AS berechnen | OSPF, IS-IS, RIP oder EIGRP |
| Routen zwischen Autonomen Systemen austauschen | BGP |
| Private IPv4-Adressen öffentlich nutzbar machen | NAT beziehungsweise NAPT |
| IPv4 langfristig ablösen | IPv6 |
| Eine feste Adresse trotz Standortwechsel behalten | Mobilitätsanker und Tunneling |

## Zusammenfassung
- Switches leiten Frames innerhalb eines LANs anhand von MAC-Adressen weiter.
- Switches lernen MAC-Adressen anhand der Quelladresse ankommender Frames.
- STP verhindert Schleifen in redundant verbundenen Switch-Netzen.
- VLANs bilden mehrere logische LANs auf gemeinsamer Hardware.
- Router verbinden unterschiedliche IP-Netze.
- Routingprotokolle berechnen Routen; Forwarding wendet die Routingtabelle auf einzelne Pakete an.
- Longest Prefix Match wählt die spezifischste passende Route.
- Link-State-Verfahren verwenden eine vollständige Topologiesicht.
- Distance-Vector-Verfahren berechnen Routen anhand der Meldungen direkter Nachbarn.
- BGP verbindet Autonome Systeme und berücksichtigt wirtschaftliche Policies.
- NAT übersetzt private IPv4-Adressen und Ports.
- IPv6 erweitert den Adressraum und vereinfacht Teile des IP-Headers.
- Mobilitätsanker verbinden eine dauerhaft bekannte Adresse mit der aktuellen Position eines mobilen Geräts.
